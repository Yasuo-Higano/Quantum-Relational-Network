## 0. 入力契約の機械化 — ラベル置換

読み出し器に渡されるのは**ノードラベルを乱数置換した状態だけ** (相関行列 /
多体波動関数)。座標・隣接関係・外部計量・格子ラベルの幾何的意味は渡さない —
隠れた添字隣接の使用は置換で壊れる (幾何を知るのは採点側だけで、置換を戻して
照合する)。クエンチ源の位置は実験側の知識であり、読み出しは状態族 ρ(t) と
源ラベルのみを見る。

## 1. 候補と共通パイプライン (FROZEN BRIDGE READOUT v29)

核 w(i,j) だけが異なり、パイプラインは共通:

| 候補 | 核 |
|---|---|
| B1 | 相互情報量 MI(i,j) = S_i + S_j − S_ij |
| B2 | 2 ノードモジュラー核 ln((1−C)/C) のノード間 off-diagonal ノルム (多体版は ‖ln ρ_ij − ln ρ_i⊗ρ_j‖_F) |
| B3 | 密度応答 \|⟨n_i n_j⟩ − ⟨n_i⟩⟨n_j⟩\| |
| B4 | 局所擾乱 (粒子注入 / ボンド演算子) の到着時刻 t*(q→j) — 因果 |

パイプライン: 橋対検出 (相互 top-1 + 3× 支配) → 相互 top-2 グラフ → 成分と位相
分類 (Cycle / Path / Other) → 巡回順 → (採点側) 隣接照合・MDS 署名。凍結定数:
W_FLOOR = 1e-8・BRIDGE_DOM = 3・EIG_CLAMP = 1e-12・FRONT_EPS = 1e-3・FRONT_DT = 0.5。

**凍結の機械化**: 読み出し節は `FROZEN BRIDGE READOUT v29` マーカーで区切られ、
v28.2 (holdout) は**この節を逐語複製して節 SHA-256 の一致を自己検査する** —
holdout を見てからの調整 (failed_bridges_rejected_not_tuned の破り) はコード上
不可能になる。節 SHA-256 = `7a28d0dbe9f7eb10f5f017eaf96e09ee5b817516a79c2871aad1b5a53bf1f772`。

## 4. 開発記録

1. **v28.0 残高 #2 (v153 の run 間ドリフト) の機構特定**: lib.rs
   `Z2CoreState::rdm` が環境キーの群化に **HashMap を使い、反復順が per-process
   乱数** — ρ の浮動小数和の順序が走行ごとに変わる (1e-15 級)。bridge 監査は
   凍結節の**決定的 rdm (BTreeMap)** を使う (lib 値と 2.8e-17 一致・2 回呼びで
   bit 同一を機械検査)。lib 側の修正は儀式コスト (~150 CPU 時間) を伴うため、
   次の lib 変更版に登録。
2. **B4 初版 (位相破壊クエンチ) は前線が読めなかった** — 二部格子+半充填の
   粒子正孔対称により局所密度がクエンチ後も厳密不変 (max|Δn| ~ 1e-15)。これは
   **v6.7 の教訓「対称性で保護された観測量は光円錐を運ばない」の再演**であり、
   独立に再発見された。クエンチを粒子注入 (占有 1 に射影・切断) に変更して
   対称性を破った — 訓練段階の設計修正 (holdout には触れていない)。

## 5. 解釈の上限 (凍結)

全 holdout を通過しても成立するのは「同じ網から時空 (的構造) が出る」という
**QRN 固有の C3 主張 (toy 機構)** まで。bridge law 登録簿
(qrn_core::REGISTERED_BRIDGE_LAWS) は空のまま — 昇格には claims 改訂 + 監査
期待値の同時更新という設計された摩擦がある。PRED-019 は登録しない。
