## 0. バグ (PROMPT/11 の独立監査が発見)

lib の `linfit` は y = a + b·x に対し **(切片 a, 傾き b)** を返す (doc 記載どおり)。
v28.2 `xi_from_order` と v28.3 `xi_envelope` は

```rust
let (slope, _) = linfit(&xs, &ys);   // ← 受けたのは切片
-1.0 / slope
```

と書き、**切片を減衰率として使用** — 公表された HOLD-3 の「ξ」は全て ξ = −1/切片
だった。バグは凍結節の**外** (採点側) にあり、読み出し規則・バー・他の holdout
セルは無傷 (v291 [E0]/[E3] で機械確認)。**他の全 linfit 呼び出し (v04/v05/v06/
v07/v11/v154 等) は `(_, slope)` で正しく、影響は bridge 採点器 2 箇所に限局**
(v29.1 の全数監査)。

## 1. 三段の検証

1. **[E1] バグの再現** — 切片版推定器 (偶距離 = v28.2 / 上包絡 = v28.3) を逐語
   再実装し、**公表値 12 系列 (ξ 6 対 + 比 6 個 × 2 推定器) を印字精度で再現**。
   「公表 ξ は −1/切片だった」が推測でなく機械的事実になった。
2. **[E2] 修正裁定** — `linfit_typed` → `KernelDecayLength` (傾きの負・有限を
   型が強制、fail-closed)。バー [0.8, 1.25] は不変:

   | 候補 | 旧「ξ比」(−1/切片) | 訂正 (KernelDecayLength 比) | 裁定 |
   |---|---|---|---|
   | B1 (MI) | 0.902 | stag 4.2609 / Wil 4.3049 = **0.9898** | 内 (ただし HOLD-1 で棄却維持) |
   | B2 (モジュラー) | 0.755 → 棄却 | stag 8.5061 / Wil 9.0096 = **0.9441** | **内 → 生存へ訂正** |
   | B3-COV | 0.968 | stag 4.2620 / Wil 4.1535 = **1.0261** | 内 (生存維持) |

   外部クロスチェック: PROMPT/11 の独立実装診断値 (0.989779 / 0.944116 /
   1.026119) と 4–5 桁一致 — 共有コードなしの第二実装が同じ数を出した
   (hard-code はしていない — 本バイナリは独立に再計算)。
3. **[E3] 非波及** — 修正と無関係な 10 セル (H1×3・H2×5・H4×2) の裁定が
   v28.3 と完全一致。

## 2. 訂正後の確定成績 (第二十九期 bridge 比較の最終表)

**生存 = B2 (モジュラー)・B3-COV・B4-DENSITY-FRONT / 棄却 = B1 (MI, 開放端の
橋誤検出 — 候補固有・全採点で不変)。**

撤回される解釈: (i) 「B2 = regulator 物性の独立再発見」— 不成立 (v24 の λ の
regulator 物性自体は独立に有効な既知結果のまま。それが**この検査で見えた**という

## 3. 意味論の同時修正 (PROMPT/11 §意味論監査)

1. **正名**: 実装された候補は B3 → **B3-COV** (density connected-covariance
   kernel)・B4 → **B4-DENSITY-FRONT** (density-threshold perturbation front)。
   事前登録の **B3-QFI/BKM・B4-COMMUTATOR/LR は未試験候補**として分離
   (v29.2 で再登録)。
2. **ξ の正名**: 「物理的相関長」ではなく **KernelDecayLength** — カーネル冪
   (|C| vs |C|²) と代数的前因子が未分離。log w = c − p·log d − q_B·κ·d 型の
   モデル選択は次段の事前登録項目。
3. **因子分解は入力である**: NodeState はモードをノードへ群化して受け取る —
   隠したのは座標・隣接・ラベルであって**部分系分解そのものではない**。成立して
   いる主張の正確な scope は「**与えられたノード因子分解の下で**、ラベル・座標・
   隣接を入力せず、隠れた 1 次元隣接・位相・因果順を回復した」。
   FactorizationBridge (分解の抽出) は別課題として分離。
4. **B4 は合成 readout**: 距離供給は B1 (リング/H2) または B2 (開放鎖) —
   「B4 単独の生存」ではなく **空間核 × 密度前線の合成**の生存。次段は
   S (空間核) × C (因果チャネル) の全組合せを独立セルで採点 (フォールバック禁止)。
5. **棄却 B1 の未使用チャネル得点 (0.9705) は生存候補の根拠に流用しない**
   (成績表に B1 の行として残すのみ)。
6. **v28.3 の再分類**: 「未観測 holdout」ではなく **post-holdout
   instrument-repair retest**。本 v29.1 も同種 (holdout は 3 回観測済み) —
   確認的証拠としての価値は逓減しており、**次の検証は新鮮な HOLD-5 以降**
   (v29.2 で候補仕様・scorer・バー・生成分布・未公開 seed を凍結してから生成)。

## 4. 型安全化と全数監査 (再発防止)

- `LinearFit { intercept, slope, r_squared }` + `linfit_typed` (fail-closed:
  点数 < 3・非有限・分散ゼロ)。**旧 `linfit`/`linfit_checked` は署名変更しない** —
  v25.2 凍結対象 (v251_gmu/v252 系) が使用しており変更は凍結破りになる
  (アドバイス「置換」からの scope された逸脱 — 理由つき)。新規・採点コードは
  typed API を使う規約とし、変成テストを **self_test に常設** (全バイナリが毎起動
  で検査): y = 3 − 0.2x → slope = −0.2, ξ = 5 / w → c·w で ξ 不変 (切片使用は
  ここで必ず落ちる) / d → 2d で ξ → 2ξ / 正傾き・点数不足・分散ゼロは fail-closed。
- **裸タプル API の全数監査**: 危険類型 = 同型 f64 対で位置に意味があるもの。
  `linfit`/`linfit_checked` (切片, 傾き — 本件・typed 代替を提供)・`mean_err`
  (平均, 誤差 — 全呼び出しを目視監査し正用を確認、スケール差で誤用が可視のため
  低リスクと分類)・`linfit` 系以外の多値 (jacobi_eigh の (値, ベクトル)・
  lanczos の (値, ベクトル, 残差)・rdm の (re, im, 次元)) は**形状が異なり取り
  違えがコンパイル/即時破綻する**ため対象外と分類。
- **同梱: Z2 rdm の BTreeMap 決定化** (lib 変更) — v28.1 で特定した v153 run 間
  ドリフト (HashMap 反復順 → ρ の FP 和順序変動) の根治。lib 変更に伴う全スイート
  再走の儀式は本版で実施 (§5)。
