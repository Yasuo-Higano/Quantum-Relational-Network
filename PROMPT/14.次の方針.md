# 結論

第三十三期の主研究は、**E3 の残り半分――「accessible operations の出自」――を閉じること**に置くべきです。

ただし、目標を「物理的に可能な操作を状態や Hamiltonian だけから自動的に導く」としてはいけません。それは原理的に無理です。同じ系でも、接続された制御器・測定器・許容時間・精度・帯域によって可アクセスな操作は変わります。

したがって次期テーゼは、次の形が適切です。

> **可アクセス性は作用素単体の属性ではなく、系・制御器・測定器・資源・誤差証明書の関係である。局所性は、証明付き laboratory interface が生成する操作文脈 atlas 上で整合する因子分解の、資源スケールにわたる安定な同値類としてのみ識別される。**

D2-R 外部公募は引き続き最優先ですが、これは**独立性トラック**であって、第三十三期の内部主定理にはしない方がよいです。外部参加者の有無を期の完結条件にすると、研究の進行が第三者の行動に従属します。一方で、内部 holdout を増やしても `external_replications = 0` は埋まりません。現在の D2-R が解除するのも `spatial_topology_given_factorization` の独立性 blocker だけであり、E3・PRED-019・自然観測・bridge law は別問題です。([GitHub][1])

# 現状監査から見える、本当の次の壁

v33.0-B の内部閉包は非常に強いです。20/20、再検証 1371/0、既存バイナリのドリフト 0、bridge law 0、自然的中 0、外部再現 0 という区別も維持されています。リポジトリ自身も次期課題として、外部再現、accessible operations、graded recovery、dim > 8 を明記しています。([GitHub][2])

しかし、コード上はさらに重要な境界があります。

## 1. 現行復元器では `contexts` が定理入力として働いていない

`OperationalNet` は `contexts` を保持し、`add_context` は可換性を検証します。しかし `recover_factorization()` は contexts を参照せず、全 primitive に対する `noncommutation_components()` を直接使っています。また、復元対象行列は net 内の operation ではなく、別引数 `gens` として並行に渡されています。現在のテスト経路では両者は整合していますが、その整合性は型で保証されていません。([GitHub][3])

これは現行定理の誤りではありません。定理の仮定が、既に「各ノードの局所生成子だけが選別された primitive family」を要求しているということです。

例えば

[
{X_1,Z_1,X_2,Z_2,X_3,Z_3}
]

なら `[2,2,2]` を復元できますが、ここに independently accessible な entangler (X_1X_2) を加えると、全 primitive の非可換グラフでは第1・第2因子が接続され、`[4,2]` 側へ併合され得ます。細粒度の局所構造を保持すべきか、実際に粗粒化すべきかは、操作コスト・文脈・合成経路なしには決まりません。

したがって次期の敵は、数値誤差ではなく、

> **primitive の選別自体が答えを入力してしまう循環**

です。

## 2. 「context = 可換集合」は役割ごとに分解する必要がある

現在は Preparation、Control、Measurement、Drift が別型になっています。これは正しい設計です。一方、単一の `add_context` が全対可換を要求する設計は、役割意味論を再び混ぜています。

* Control context は、非可換な (X) と (Z) を独立に操作できることを含み得ます。
* Measurement context は joint measurability であり、一般 POVM では単なる可換性より広い概念です。
* Preparation context は凸可達性や同一装置設定の族です。
* Drift context は固定された環境・時間窓です。

一般 POVM の joint measurability は、作用素の可換性だけでは特徴づけられません。非可換な unsharp measurement が共同測定可能な場合もあります。([arXiv][4])

したがって、次期には少なくとも次を別型にすべきです。

```text
ControlContext
  └─ IndependentAddressabilityCertificate

MeasurementContext
  └─ JointMeasurementCertificate

PreparationFamily
  └─ ConvexReachabilityCertificate

DriftRegime
  └─ StabilityCertificate

AlgebraicCommutatorCertificate
  └─ 上記 context 証明書への暗黙変換なし
```

## 3. 現在の Liouvillian は Hamiltonian commutator lane

v32.4 の実装対象は明確に

[
\mathcal L_H(A)=-i[H,A]
]

であり、応答は (R^{(1)})、(R^{(2)}) の Hamiltonian commutator 恒等式です。一般の GKLS 生成子ではありません。([GitHub][5])

「Liouvillian」という語自体は間違いではありませんが、claims と型では次を分離すべきです。

```text
HamiltonianCommutatorLiouvillian
GklsLiouvillian
UnknownGenerator
```

現行証明書から `GklsLiouvillian` への昇格は禁止します。一般 GKLS への拡張は次々期の独立テーマにできます。

# 第三十三期の科学的中心

E3 を次の二つに分けます。

## A. controller-free decomposition no-go

次を新しい no-go として閉じます。

> 同一の ((\mathcal H,H,\rho)) に対して、異なる laboratory interface が非同値な OperationalNet と因子分解を生成し得る。したがって、状態・Hamiltonian・大域作用素代数だけから「物理的に accessible な操作」を一意に選ぶ写像は存在しない。

これは、

1. 状態単独では因子分解を選べない
2. global closure は marking を消す
3. controller を消すと accessibility が消える

という三段の no-go を完成させます。

## B. factorization given a certified laboratory interface

正側は次です。

> 校正済みの preparation/control/measurement interface、独立 addressability、合成経路、誤差区間、資源上限が与えられたとき、それらから AccessibleOperationalNet を構成し、因子分解・superselection・同値類・abstention を証明書つきで返す。

「accessible operations を入力として与えた」から、

「各 operation が、どの command、校正、合成列、誤差、資源によって accessible なのかを証明した」

へ進めます。

「subsystem structure は accessible interactions and measurements に依存する」という原理自体は既知です。Zanardi–Lidar–Lloyd は既に observable-induced tensor product structure を提示し、Zanardi らの Operational Quantum Mereology は algebra と commutant による gTPS と、短時間 scrambling による動的選択基準を研究しています。([arXiv][6])

* role-typed context atlas
* resource-indexed factorization profile
* context overlap 上の整合・非整合の裁定
* graded Majorana/Dirac no-go
* adversarial holdout と外部再現契約

# v33.2 で導入すべき型

概念的には次の構造が必要です。

```rust
enum OperationOrigin {
    DirectlyCalibrated(CalibrationCertificate),
    Synthesized(SynthesisCertificate),
    TomographicallyInferred(TomographyCertificate),
}

struct IndependentAddressabilityCertificate {
    command_jacobian_rank: CertifiedRank,
    smallest_singular_value: Interval,
    crosstalk_bound: Interval,
    calibration_hash: Sha256,
}

struct ResourceBudget {
    max_duration: TimeBound,
    max_amplitude: AmplitudeBound,
    max_bandwidth: BandwidthBound,
    max_depth: DepthBound,
    max_error: ErrorBound,
}

struct AccessibleOperation<Role, Grading> {
    operation: Role,
    origin: OperationOrigin,
    addressability: IndependentAddressabilityCertificate,
    budget: ResourceBudget,
}
```

重要なのは `ResourceBudget` を早急に単一スカラーへ潰さないことです。時間、エネルギー、帯域、精度の恣意的な重み付き和は、新しい選択バイアスになります。最初は componentwise partial order を持つ有限 poset として扱う方が安全です。

新しい禁止変換は少なくとも次です。

```text
DeclaredOperation
    ↛ AccessibleOperation

AlgebraicCommutation
    ↛ OperationalCompatibility

OperatorDecomposition
    ↛ IndependentlyAddressablePrimitives

HamiltonianCommutatorResponse
    ↛ GeneralGKLSResponse
```

特に三番目が重要です。装置が (u(t)(X_1+X_2)) しか操作できないとき、行列を (X_1) と (X_2) に数学的分解して「二つの独立 primitive」と扱ってはいけません。

# v33.3 の中心対象は「単一因子分解」でなく profile

可アクセス性は resource budget に依存します。

典型的には、

```text
資源不足       → Abstain
局所制御可能   → [2,2,2]
entangler可能  → [4,2] または [8]
完全制御可能   → global closure
```

となります。

したがって、最終 budget だけを見ると v32.2 の erasure no-go に戻ります。必要なのは、

```text
OperationalFactorizationProfile:
    ResourceBudget ↦ FactorizationReading
```

です。

重要な点は、通常の persistent homology と同一視しないことです。因子分解は予算増加で分裂も併合も起こり得るので、最初から「barcode」と呼ぶべきではありません。まず有限 poset 上の constructible profile として定義し、写像と安定性定理が成立した後に zigzag persistence 等へ進めます。

昇格可能な局所性は、

> 単一閾値で一瞬だけ出現した因子分解

ではなく、

> 誤差・budget perturbation に対して一定領域で同じ gauge orbit を保つ因子分解

とします。

# v33.5 graded lane は、まず no-go を立てる

現在の課題表現は「odd 演算子からモード構造を復元」ですが、odd CAR だけから通常の複素 fermion mode を一意に得ることはできません。

(2N) 個の Majorana generator の CAR は実直交変換 (O(2N)) に不変です。一方、Majorana を二本ずつ組にして annihilation/creation operator を定めるには、実空間上の直交複素構造

[
J^2=-I
]

が追加で必要です。複素構造が fermionic creation/annihilation representation を定めることは既存の数学的記述とも整合します。([arXiv][7])

したがって、正しい出力階層は次です。

```text
odd CAR only
  → MajoranaFrame / O(2N)-orbit
  → Dirac mode は EquivalenceClassOnly

odd CAR + charge or complex-structure witness
  → ComplexModeFactorization
  → U(N) gauge を除いて回復

degenerate/noisy charge witness
  → Abstain(ComplexStructureUnresolved)
```

これは非常に強い次期成果になります。

> **Majorana locality と Dirac-mode locality は同じ識別問題ではない。後者は追加の U(1) charge / complex structure を必要とする。**

現行 `FermionicZ2Graded` を単に非可換グラフへ通すだけでは不十分です。異なる Majorana は graded bracket では可換扱いになるため、それだけでは「どの二本を一つの複素モードに組むか」を決められません。

# スケーリング方針

一般 dense matrix の (*)-closure をそのまま高速化して「大型系へスケールした」と主張してはいけません。qubit 数に対して行列次元自体が指数増大します。

次の三 lane を明示的に分けます。

```text
GenericDenseBackend
  scope: 小次元の完全一般系

PauliSymplecticBackend
  scope: Pauli/Clifford 型
  representation: GF(2)^{2n} + phase
  commutation/centralizer: exact linear algebra

MajoranaQuadraticBackend
  scope: quadratic fermion / Majorana bilinear
  representation: real antisymmetric matrices
```

成功条件は、例えば次です。

* n ≤ 8 の全既存セルで dense と exact backend が完全一致
* Pauli lane は 32–64 qubit まで行列を生成せず証明書を返す
* Majorana quadratic lane も同程度の mode 数で動作
* generic dense の結果を一般大型系へ昇格しない
* `ScopeExceeded` を正しい裁定として実装する

これは物理証拠ではなく、**プロトコルが外部化可能かを測るメタ実験**です。
